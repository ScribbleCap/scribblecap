# Packaging and releases

Pushing a tag `v<workspace version>` runs `.github/workflows/release.yml`.
For example, workspace version `0.1.0` requires tag `v0.1.0`. Update
`Cargo.toml` and `Cargo.lock` together before tagging. Tags with a prerelease
suffix create a prerelease draft. The workflow creates one draft, then builds:

| Platform | Architecture | Downloads |
|---|---|---|
| macOS 14+ | Apple Silicon and Intel, separate builds | `.dmg` |
| Windows | x86_64 | `.msi` |
| Linux | x86_64 (Ubuntu 22.04 build environment) | `.AppImage`, `.deb` |

The UI builds before Rust through Tauri's `beforeBuildCommand`. Packaging uses
the repository's pinned Rust, Node, pnpm and Tauri CLI, with locked dependencies.
Only the release jobs have permission to write releases. No signing secrets are
required. Re-running a failed job reuses the draft; the workflow refuses to
modify an already published release. A partial build remains a draft.

## Before publishing the draft

1. Confirm CI is green for the tagged commit and all four packaging jobs passed.
2. Download every installer from the draft, install on each supported OS and
   architecture, and check open, annotate, copy, save and reopen. Check Linux
   AppImage and Debian installation separately. Record the tested OS versions.
3. Check that the draft contains both macOS architectures, the Windows MSI,
   AppImage and Debian package. Include known limitations in release notes.
4. Publish the draft manually when the checks above pass.

## Unsigned builds

Until signing is configured, macOS downloads have no Apple Developer ID signature
or notarisation. Gatekeeper can block launching them. Follow the operating
system's documented approval flow only for a download you trust; do not disable
Gatekeeper globally. Windows MSI downloads have no publisher signature, so
SmartScreen or local policy may warn or block installation. Managed machines may
require administrator approval. Linux packages are also unsigned.

Apple Developer ID signing/notarisation and Windows SignPath Foundation signing
remain follow-ups. Flathub submission is separate. No signed updater feed is
generated by this workflow.

Workflow reference: [Tauri GitHub Actions guide](https://v2.tauri.app/distribute/pipelines/github/)
and [tauri-action inputs](https://github.com/tauri-apps/tauri-action).
